API Documentation

Accept UPI payments on your website, app or bot. Works with Paytm and FamPay. Base URL: {{base}}

1How it works

  1. Your server creates a payment with the amount and your own order id.
  2. You receive a payment_url (QR page), a QR image and the upi_uri.
  3. The customer scans the QR and pays with any UPI app.
  4. We verify the payment automatically and mark it SUCCESS only if order id and amount match.
  5. We send a signed webhook to your server (or you poll verify). Deliver the product only then.

2Quick start

  1. Open Gateways and save your setup, then press Test: pay Rs 1 and pay it. “Payment Successful” means it works.
  2. Open API Keys and create a key. Copy it (shown once).
  3. Call the API from your server (examples below). Never put the key in website JavaScript or an app.

3Paytm or FamPay

Choose with the gateway field: "gateway":"paytm" or "gateway":"fampay". Always send it. If you leave it out, the first enabled gateway is used (FamPay first, then Paytm).

Paytm

  • Setup: Shop Name, UPI ID, MID
  • Customer pays the exact amount
  • Verified automatically through Paytm
  • Result is usually instant

FamPay

  • Setup: Shop Name, UPI ID, Gmail, Gmail App Password
  • Amount gets a unique paise adjustment (+0.00 to +0.99)
  • Verified from the bank email in your Gmail
  • Can take a few seconds to a minute
FamPay amount: if you ask for 99.00 the response may say amount: 99.37. The customer must pay exactly the amount returned. Show that amount to the customer.

Your plan must include the gateway you use, otherwise you get 403 Gateway not included in your plan.

unpaid → {"status":"pending|failed|expired","data":null}

order_id can be your order id or the pay_id. Poll every 3–5 seconds, or use webhooks.

StatusMeaning
PENDINGWaiting for the customer
SUCCESSPaid and verified. The only status that means paid
FAILEDProvider reported a failure
EXPIREDNot paid within 10 minutes

7Webhooks (automatic success message)

Set your https URL in Webhooks and copy the signing secret. Events: payment.success, payment.failed, payment.expired, webhook.test.

Headers:  X-Payment-Gateway-Timestamp: 1731234567
          X-Payment-Gateway-Signature: sha256=HEX
Signature = HMAC_SHA256(secret, timestamp + "." + rawBody)

{"event":"payment.success","event_id":"PTM2026...:payment.success",
 "order_id":"ORDER10001","pay_id":"PTM2026...","transaction_id":"123456789012",
 "amount":99.0,"currency":"INR","status":"SUCCESS","gateway":"paytm"}
  • Sign the raw body, not re-encoded JSON
  • Reject timestamps older than 5 minutes
  • Compare signatures in constant time
  • Ignore duplicate event_id
  • Reply with any 2xx; failed deliveries are retried
  • Check status = SUCCESS and the amount before delivering

10Code examples

Replace GATEWAY with "paytm" or "fampay".

Python

import hmac, hashlib, time, requests
from flask import Flask, request, abort
BASE = "{{base}}"; KEY = "YOUR_KEY"; SECRET = "WEBHOOK_SECRET"
GATEWAY = "paytm"   # or "fampay"
app = Flask(__name__)

def create_payment(amount, order_id):
    r = requests.post(BASE + "/api/v1/payment/create", headers={"X-API-Key": KEY},
        json={"amount": amount, "order_id": order_id, "gateway": GATEWAY}, timeout=20)
    r.raise_for_status()
    return r.json()     # payment_url, qr_png_url, amount

@app.post("/payment-webhook")
def webhook():
    ts = request.headers.get("X-Payment-Gateway-Timestamp", "0")
    sig = request.headers.get("X-Payment-Gateway-Signature", "")
    body = request.get_data(as_text=True)
    exp = "sha256=" + hmac.new(SECRET.encode(), (ts + "." + body).encode(), hashlib.sha256).hexdigest()
    if abs(time.time() - int(ts)) > 300 or not hmac.compare_digest(exp, sig): abort(401)
    d = request.get_json()
    if d["event"] == "payment.success" and d["status"] == "SUCCESS":
        pass            # deliver the order ONCE per d["event_id"]
    return "ok"

12Security checklist

  • API key and webhook secret only on your server
  • Verify the webhook signature and timestamp
  • Check status and amount before delivering
  • Make delivery idempotent (event_id / order_id)
  • Use a unique order_id for every purchase
  • Use https for your webhook URL
